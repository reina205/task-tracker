# Reflection — Mid-Course Project

*(Draft based on our actual session — please read this over and adjust anything that doesn't match your real experience before submitting.)*

For this project, I used Claude to help implement both features on top of my existing Task Tracker: due dates with an overdue filter, and tags/labels. I worked through the full ask → inspect → run → test → refine loop for each one, rather than accepting generated code without checking it.

One place AI genuinely helped was speed and thoroughness on the backend logic. When I asked for the due-date model changes, Claude didn't just add a field — it proposed computing "overdue" as a read-time property rather than a stored one, which meant the value would always reflect the current date instead of going stale. It also generated a fairly complete set of edge-case tests on the first pass (invalid formats, the Done-task exception, filtering with no matches) that lined up closely with the "good tests to include" column in the assignment brief, so I didn't have to invent every edge case myself. The Break Tests were useful too: deliberately feeding malformed input (a number instead of a string, a tag over the length limit, explicit `null`) confirmed the validation actually worked rather than just looking plausible in the code.

Where it slowed me down was less about the code itself and more about my own environment. I didn't have Git or a clear terminal workflow set up beforehand, so a large part of the actual time went into installing Git, learning to open a terminal in the right folder, and — most frustrating — copy-pasting file contents into Notepad correctly. At one point a paste landed without a line break and merged two lines together, causing a Python syntax error that took a few back-and-forth screenshots to diagnose and fix. That wasn't really an AI mistake, but it's a real part of what "AI-assisted coding" looks like when you're also learning the surrounding tools at the same time.

The moment my own review most changed the result was the overdue-date design decision. Claude's first draft of the user stories left it ambiguous whether "overdue" should be computed in the frontend or backend. I made myself pick backend explicitly, since it's testable with pytest and consistent no matter what calls the API — and that decision shaped the rest of the implementation. I also caught a real bug during manual testing: I'd mistyped a due date's year, and only noticed because I was actually clicking through the app in the browser rather than trusting that the tests passing meant everything was fine.
